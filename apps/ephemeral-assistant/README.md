# Auction Moment Ephemeral Assistant

> **休眠与验证边界：** “竞拍时刻”活动已经下线，本子项目自 2026-08-06 起只作为实验原型和返场恢复基线保留。它没有在正式活动环境完成一整局从开局、五轮推理到对局结束的端到端跑通验证；下述内容描述的是已经实现的组件和设计流程，不是生产可用性声明。

这是公开研究仓库中的独立半自动实时估值助手原型，有两种证据来源：

- **被动抓包（默认，`--input packet`）**：通过 ADB 在已 root 的模拟器内运行
  `tcpdump`，只监听 tcp/8002，在本机内存中解码。每轮个人事件结果到达后即输出预测。
  详见下方“抓包输入”。
- **截图 OCR/YOLO（`--input ocr`）**：状态机常驻读取 `1280×720` 画面，大厅待机，
  检测开局，在每轮出价前自动归顶并分段扫描地图，识别完成后恢复顶部、输出预测并
  待机。RapidOCR 和 Release 中的三份 YOLO 权重负责识别。

两种来源都交给最新冻结的 v6 + world-model-v2；默认估值器是精确条件后验。

运行时不包含任意点击、键盘输入或自动出价；自动输入能力只有 OCR 模式下两种固定
的左侧地图滚动手势。抓包只读取并解码出价前可见的三类消息，不解码结算、排名、
出价和玩家身份。不保存抓包数据、截图、OCR、人工修改、预测或最终结算。
静态模型文件是唯一允许持久化的运行资产。最新 v6 的
候选 ID 是 `protocol-round-residual-v6-72a08074c3d8af81`。

左侧地图建模画布与原 OCR 校对语义一致：`左上角位置` 和 `完整形状` 分别可与
`无品质/白/蓝/紫/金/彩` 组合，再加 `完整身份`，共 13 类。标注框的显示几何
不会被当成左上提示的真实尺寸。人工标注完整身份时，必须先选地图框，再从按
已知品质/尺寸过滤的图鉴列表明确确认；拖动可移动，右键可删除。右侧按轮列出
公共/个人事件，选中即可修正。图鉴选择器显示 120 项中文名称、品质、尺寸、
价值和对应的 80x80 缩略图，不再要求用户记忆内部编号。所有修改只驻留内存
并立即重算。

OCR 转义层不会伪造抓包字段：事件必须达到 OCR 阈值或经人工修正；自动扫描的
地图行数明确标为估算，用户可复核后升级为人工精确确认。达到置信度阈值且通过
图鉴品质/尺寸一致性检查的 YOLO 完整身份默认采用；用户可从同一图鉴列表改正。
人工升级为完整身份时仍须明确确认具体图鉴项。OCR 路径与原始结构化输入不等价，
区间仍未校准，所有结果固定为 `actionable=false`。

每轮估值同时显示一个不会自动提交的手动建议价：默认取融合 P10 的 90% 作为
价值侧收购上限，并按本轮中标倍率反算可兼容的对手最高报价。若 v2 条件组合
找不到兼容世界，界面会保留 v6 P10/P50/P90 和 v6 保守建议价，并用中文指出
最后是哪条事件、可见数量、身份、品质或尺寸约束使兼容世界归零。可用
`--bid-safety-factor` 调整展示系数；它不会开启点击或报价提交能力。

2026-10-19 的源码修订默认以修复后的 v6 作为点预测与建议价来源，v2 保留为诊断
（此后默认估值器已改为精确条件后验，见下文；`--v6-only` 恢复只用 v6）。
原 40%–80% 启发式融合需显式设置 `--experimental-v2-fusion`；新条件采样与严格融合门
需显式设置 `--experimental-conditional-sampling`。临时关闭默认融合的依据及其事后选择
边界见下方配对回放结果；这些实验选项均没有通过新时间块的精度资格验证。

此次修复了 OCR 适配层丢弃随机揭示历史的问题。只有完整、可信且能唯一归因的首次身份/品质揭示
才进入冻结 v6 对应特征；OCR 来源仍保留为 `ocr_thresholded`，不伪造协议或人工确认。
缺少历史、多揭示来源、低置信度或属性出现时点不清时不补造历史。

默认经验先验增加独立复核：1794 个公开世界中有 302 个图鉴总价与结算不一致；综合
协议确认、计数、独立身份/几何与复核状态后，1284 个合格、510 个排除。标签有效而
身份不可靠的局仍可参与评分，不能用清洗先验的理由删除误差较大的评分局。
详见[可重跑审计](../../scripts/audit_public_world_quality.py)、[审计结果](../../results/public-world-quality-audit-20261019.json)
与[审计 notebook](../../notebooks/public-world-quality-audit-20261019.ipynb)。

新的条件采样链尚未超过精度基线，必须显式设置 `--experimental-conditional-sampling`
才能启用。它使用冻结 world-model-v2 的生成先验，保留具体入场顺序，按十列、不旋转、
行优先首可放规则生成地图，并严格核对
精确高度、可见锚点、已知形状、品质和身份。估算行数不当作精确高度。完整可信扫描下，
“显示所有某类藏品”还约束该类藏品不能出现在未显示的锚点。

数量先验与入场排列概率分别计算。可唯一归因的最早一次随机揭示按无放回抽样处理；
具体位置已进入布局约束时使用位置选择概率，避免重复计算品质或身份信息。缺少揭示
历史、多来源或不完整结果会明确诊断并跳过该项似然，后续随机揭示不假设独立。
“最大占格藏品轮廓”的对象绑定暂未支持，真实输入遇到该项时回退 v6。

实验模式先进行固定批量先验拒绝采样；支持不足时由 CP-SAT 搜索可行初始状态，再进行
完整块 Gibbs、顺序/身份 MH 与保持统计等式的多身份更新。求解器找到的解不被当作等
概率世界；未完整枚举的条件块不会用于抽样。整数枚举按小块检查截止时间，防止大网格
吞掉整个预算。实验模式默认预算 2 秒，可用 `--conditional-budget-seconds 8` 调整。
初始化和收敛诊断另有少量耗时，预算不是整个界面响应的硬截止时间。

实验模式融合要求收敛检查通过、有效样本数及保留样本数至少 32，监控总价、数量、品质
和各身份的链间差异与自相关。其 v2 权重按支持量限制在 10%–40%；采样失败或支持
不足回退 v6。显式选择原启发式融合时，不给有限世界过滤伪造 ESS 或收敛结论；默认
模式的 v2 权重为零，不把主动禁用融合标成采样失败。
两种模式均不会把有限样本耗尽或超时写成已证明的数值条件无解。
这些阈值是工程门控，不能证明所有模态均已发现，P10/P90 和融合权重仍未校准。
有限预算未收敛结果不会永久缓存，可在相同证据下重新计算；后续尝试使用不同种子，
并记录尝试编号，首次尝试仍保持冻结开发回放的种子。这不保证重试能够收敛。

此修订尚未发布为新版本，也没有重新训练冻结模型。公开事件回放脚本是
`scripts/evaluate_assistant_conditioning.py`：它剔除所有评分局的经验先验行，并将标签
仅用于评分，但冻结模型的训练窗口与公开数据重叠，结果只属开发诊断。公开数据缺少
真实逐轮地图、精确高度和随机揭示对象，不能据此证明布局收益或真实助手的精度提升。

### 抓包输入（默认）

**解码范围**（`packet_protocol.py`）
- 只解码三类服务器消息：开局（只取地图总行数，玩家条目跳过）、每轮公共事件
  offer（事件代码、显示值、揭示的藏品）、本人个人事件结果（同上）。
- 其余消息在解码前丢弃，结算、排名、出价和玩家身份不会进入助手。
- 发布检查（`scripts/verify_public_release.py`）禁止助手源码出现这些消息的命令码。

**采集方式**（`packet_capture.py`）
- 检查 root ADB 与模拟器内的 `tcpdump`，通过 `adb exec-out` 读取 PCAP 流，在内存中
  做 TCP 重组和解码。
- 本机不写任何文件；模拟器内只写一个 pid 文件，用于停止对应的 tcpdump，停止时删除。
- `--packet-pcap` 可改为回放 PCAP 文件；`--packet-interface`（默认 `wlan0`）和
  `--protocol-port`（默认 8002）可调。

**模型输入**（`packet_session.py`）
- 事件含义来自公开的 `data/v1/core/event_catalog.csv`（46 个事件代码）。
- 每轮生成两份输入：
  - 与 10/19 受控转录回放同样规则的 `ObservationSnapshot`，经原适配层交给 v6；
  - 逐轮决策记录，由 `exact_evidence.evidence_from_decision` 直接交给精确采样。
- 地图总行数取自开局消息（精确）；随机揭示抽到了哪几件是已知的，不需要按屏幕归因。
- 本轮公共事件到达时即用部分记录预热精确采样。
- 人工修改优先于抓包证据；修改后本轮按屏幕证据规则估值，“重扫”恢复抓包证据。
- 需要从开局消息开始抓包；中途启动时，本局显示“抓包证据不可用”，下一局恢复正常。

**与评估输入的一致性**
- 用已消费 74 局记录的原始服务器消息逐帧回放：628 条可见消息的解码结果与记录一致。
- 277 份决策的决策记录、快照事件与地图、地图行数全部与评估输入相同。
- v6 估值与冻结记录完全一致，精确采样的证据与基准相同。

### 精确条件后验（默认估值器）

精确条件后验是默认估值器，`--v6-only` 可关闭。选择 `--experimental-v2-fusion` 或
`--experimental-conditional-sampling` 时它自动关闭，两者不能同时使用。
`--experimental-exact-sampling` 仅为兼容旧命令保留。

**推断方式**
- 在冻结 world-model-v2 先验下做精确约束重要性采样。
- 数量、总价、平均面积、最高价值、最高每格价值、最高品质、总占格数和尺寸平均价值，
  在每个返回世界中都严格成立，不放宽，也不近似。
- 尺寸平均价值先逐品质精确枚举该尺寸藏品的组合，只抽取平均值向下取整等于显示值的组合。

**输出**
- 估值取后验的期望相对误差最小点，即按 1/价值加权的中位数，并同时显示后验
  P10/P50/P90。
- 建议价仍为 P10 × 安全系数。
- v6 照常计算，只作对照和回退。

**OCR 证据的翻译规则**（`exact_evidence.py`，仅 `--input ocr`；抓包输入直接使用决策记录）
- 只有在完整可信扫描下，“显示所有某品质/某尺寸”的事件才转为精确数量。
- “最大占格藏品轮廓”：该藏品的轮廓一直留在地图上，所以完整可信扫描中已知尺寸的
  最大面积就是全局最大面积。若事件当轮出现了无法由“随机显示位置”解释的裸锚点
  （首次出现时既无尺寸也无品质），说明有轮廓没读出，此时该条件记为忽略
  （`largest_outline_not_read`）。
- 随机揭示只计入可唯一归因的部分：
  - 完整身份只能来自随机完整揭示；
  - 观测库记录每个锚点首次显示品质的轮次（`quality_first_round`）。品质首次显示在
    含随机品质揭示、且没有同品质全显事件的轮次，才计为一次抽取；
  - 若某轮这样的品质多于该轮随机揭示的件数，说明另有来源，该轮全部不计；
  - 抽到品质早已可见的藏品，屏幕上看不出来，只能不计。
- 以下证据记为忽略，后验仍然有效，只是信息更少：
  - “随机显示位置”（只含位置）；
  - 自动估算的地图行数。
- 暂不支持的事件（如藏品总数）或相互冲突的条件直接回退 v6，不会被静默丢弃。

**运行方式**
- 启动时创建 `--exact-lanes` 个工作进程（默认 4）。每个进程独立采样 1/L 的数量向量和
  世界，最后合并；进程间离散度即蒙特卡洛误差（`lane_rel_se`）。
- 每次估值预算为 `--exact-budget-seconds`（默认 8 秒）。预算内没算完的部分，要么作为
  无偏优先抽样保留并标为“有效样本不足”，要么整轮丢弃。
- 本轮事件读出后（地图仍在滚动扫描），工作进程即用已知证据预热候选池和尺寸平均
  价值表。扫描结束后的正式估值会先取消预热，再复用缓存。
- 若估值因预算标为“有效样本不足”，工作进程在后台用 `--exact-refine-seconds`
  （默认 45 秒，0 为关闭）继续同一决策：独立种子，复用已建缓存。证据未变且收敛时，
  界面替换为细化后的估值；未收敛则保留原估值。新的估值请求或下一轮预热会先取消它，
  不会拖慢新任务。
- 该模式依赖 scipy（随 scikit-learn 安装），只在内存中运行，不写任何文件。
- 采样过程中抛出的异常记为 `exact_sampling_failed` 并回退 v6。2026-10-23 修复了一个会触发它的缓存
  错误：同一候选池可按尺寸件数或按（件数, 价值）组合分组，旧版本把两种分组的索引存在同一个键下。
  一局先有“尺寸平均价值”、后出现某品质总价值时，后一轮会读到前一轮的分组，从错误的位置抽候选，
  分组越界时报错。现在两种分组分开缓存。

**开发回放**

与上文同一批已经消费的 74 局、277 份报价前缀，不是盲测。前六行的输入是理想转录的
`ObservationSnapshot`，最后一行由记录的原始服务器消息逐帧经过助手的抓包解码得到。真实助手
按对局顺序逐个决策估值；“预热”各行先用扫描前（抓包：本轮公共事件到达时）可知的证据预热，
再等待 3 秒模拟扫描剩余时间（抓包：等待个人事件结果），只计正式估值的耗时：

| 方法 | MAPE | 有效样本不足 | 中位 / p90 / 最长耗时 |
| --- | ---: | ---: | --- |
| 修复后的 v6 单独输出 | 22.48% | — | — |
| 精确条件后验，4 进程 | 16.05% | 22 | 1.3 / 5.0 / 7.0 秒 |
| 精确条件后验，4 进程 + 预热（默认设置） | 16.19% | 17 | 0.5 / 3.9 / 7.5 秒 |
| 精确条件后验，1 进程 | 16.34% | 27 | 1.8 / 5.7 / 7.2 秒 |
| 精确条件后验，1 进程 + 预热 | 16.18% | 24 | 1.7 / 5.8 / 9.6 秒 |
| 精确条件后验，4 进程 + 预热，按实时视觉还原地图（OCR 模式当前规则） | 15.54% | 17 | 0.7 / 4.3 / 7.4 秒 |
| 精确条件后验，4 进程 + 预热，抓包输入（默认） | 15.55% | 12 | 0.3 / 3.6 / 7.2 秒 |

这批输入在研究过程中已被反复查看，结果只属开发诊断。新对局上的精度须由独立时间块验证。
其中 109 份含尺寸平均价值的决策为 15.4%–16.0%，v6 为 26.09%。同批结构化协议输入为 15.61%。
前五行使用 10/19 回放快照：它只为“按尺寸显示轮廓”保留轮廓尺寸，最大轮廓因此读不出，
随机品质揭示也只能按首次出现归因，比协议输入约差 0.4–0.7 个百分点。实时视觉会读出每个
轮廓的尺寸，观测库现在也记录品质首次显示的轮次；按这样还原的地图（最后一行），277 份决策的
证据与协议输入完全一致（随机品质揭示只比较屏幕上可见的抽取），误差为 15.54%。其中 17 份
标为“有效样本不足”的决策误差 13.5%，不限时为 13.8%。后台细化时，另一次运行标记的 16 份中
12 份在 3.7–41 秒内收敛，精度不变（全体 15.52% → 15.53%），作用只是让多数标记换成收敛估值。
1 进程加预热时，277 份中有 1 份超过 8 秒（9.6 秒）。抓包输入与结构化协议输入逐项相同，
15.55% 与 15.54%/15.61% 的差别来自采样随机性；含尺寸平均价值的 109 份为 15.57%，
相对 v6 的配对差为 −6.76 个百分点（按对局自助法 95% 区间 −11.1 到 −2.7）。抓包一行是修复尺寸平均
分组缓存（见下）之后重跑的结果，修复前为 15.57%；其余各行在修复前运行，差别同样在采样随机性以内。

回放中的地图总行数均为确认值。抓包输入的行数取自开局消息；OCR 模式实时使用时，只有每轮勾选“已人工确认到底部”后才使用行数；
同一回放（结构化协议输入、不限时）去掉行数后误差从 15.58% 升到 19.33%，是单项最重要的人工确认。

右侧运行与诊断日志区保留状态切换、完整 OCR 文本/语义、地图快照、推理契约、
issues、diagnostics 和异常堆栈。日志仅驻留当前进程内存，不写文件；区域可滚动、
选择后复制，也提供“复制全部”和右键菜单。本局清空时日志继续保留，只有用户

按设计，启动后不需要再点击“开始识别”：程序会自动进入大厅监视。需要纠错时直接操作
左侧地图或右侧事件；“立即重扫本轮”只在轮次主界面使用。

`--model-base-url` 指向兼容镜像。下载器只写入静态模型目录，不写入任何
对局数据。

程序只加载清单中固定大小和 SHA-256 的 `joblib`。Joblib/pickle 文件可能在
加载时执行代码，请勿把同名的第三方文件放入模型目录。
