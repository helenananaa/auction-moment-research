# Auction Moment Ephemeral Assistant

> **休眠与验证边界：** “竞拍时刻”活动已经下线，本子项目自 2026-08-06 起只作为实验原型和返场恢复基线保留。它没有在正式活动环境完成一整局从开局、五轮推理到对局结束的端到端跑通验证；下述内容描述的是已经实现的组件和设计流程，不是生产可用性声明。

这是公开研究仓库中的独立半自动实时视觉助手原型。状态机设计为常驻读取 `1280×720`
画面：大厅待机，检测开局，在每轮出价前自动归顶并分段扫描地图，识别完成后
恢复顶部、输出预测并待机。RapidOCR 和 Release 中的三份 YOLO 权重负责中间
过程识别，公开 OCR 转义层调用最新冻结的 v6 + world-model-v2。

运行时不包含抓包、协议解析、任意点击、键盘输入或自动出价；自动输入能力只有
两种固定的左侧地图滚动手势。不保存截图、OCR、人工修改、预测或最终结算。
静态模型文件是唯一允许持久化的运行资产。最新 v6 的
候选 ID 是 `protocol-round-residual-v6-72a08074c3d8af81`。

左侧地图建模画布与原 OCR 校对语义一致：`左上角位置` 和 `完整形状` 分别可与
`无品质/白/蓝/紫/金/彩` 组合，再加 `完整身份`，共 13 类。标注框的显示几何
不会被当成左上提示的真实尺寸。人工标注完整身份时，必须先选地图框，再从按
已知品质/尺寸过滤的图鉴列表明确确认；拖动可移动，右键可删除。右侧按轮列出
公共/个人事件，选中即可修正。图鉴选择器显示 120 项中文名称、品质、尺寸、
价值和对应的 80x80 缩略图，不再要求用户记忆内部编号。所有修改只驻留内存
并立即重算。

OCR 转义层不会伪造抓包字段：事件必须达到 OCR 阈值或经人工修正；自动扫描的
地图行数明确标为估算，用户可复核后升级为人工精确确认。达到置信度阈值且通过
图鉴品质/尺寸一致性检查的 YOLO 完整身份默认采用；用户可从同一图鉴列表改正。
人工升级为完整身份时仍须明确确认具体图鉴项。OCR 路径与原始结构化输入不等价，
区间仍未校准，所有结果固定为 `actionable=false`。

每轮估值同时显示一个不会自动提交的手动建议价：默认取融合 P10 的 90% 作为
价值侧收购上限，并按本轮中标倍率反算可兼容的对手最高报价。若 v2 条件组合
找不到兼容世界，界面会保留 v6 P10/P50/P90 和 v6 保守建议价，并用中文指出
最后是哪条事件、可见数量、身份、品质或尺寸约束使兼容世界归零。可用
`--bid-safety-factor` 调整展示系数；它不会开启点击或报价提交能力。

2026-10-19 的源码修订默认以修复后的 v6 作为点预测与建议价来源，v2 保留为诊断。
原 40%–80% 启发式融合需显式设置 `--experimental-v2-fusion`；新条件采样与严格融合门
需显式设置 `--experimental-conditional-sampling`。临时关闭默认融合的依据及其事后选择
边界见下方配对回放结果；这些实验选项均没有通过新时间块的精度资格验证。

此次修复了 OCR 适配层丢弃随机揭示历史的问题。只有完整、可信且能唯一归因的首次身份/品质揭示
才进入冻结 v6 对应特征；OCR 来源仍保留为 `ocr_thresholded`，不伪造协议或人工确认。
缺少历史、多揭示来源、低置信度或属性出现时点不清时不补造历史。

默认经验先验增加独立复核：1794 个公开世界中有 302 个图鉴总价与结算不一致；综合
协议确认、计数、独立身份/几何与复核状态后，1284 个合格、510 个排除。标签有效而
身份不可靠的局仍可参与评分，不能用清洗先验的理由删除误差较大的评分局。
详见[可重跑审计](../../scripts/audit_public_world_quality.py)、[审计结果](../../results/public-world-quality-audit-20261019.json)
与[审计 notebook](../../notebooks/public-world-quality-audit-20261019.ipynb)。

新的条件采样链尚未超过精度基线，必须显式设置 `--experimental-conditional-sampling`
才能启用。它使用冻结 world-model-v2 的生成先验，保留具体入场顺序，按十列、不旋转、
行优先首可放规则生成地图，并严格核对
精确高度、可见锚点、已知形状、品质和身份。估算行数不当作精确高度。完整可信扫描下，
“显示所有某类藏品”还约束该类藏品不能出现在未显示的锚点。

数量先验与入场排列概率分别计算。可唯一归因的最早一次随机揭示按无放回抽样处理；
具体位置已进入布局约束时使用位置选择概率，避免重复计算品质或身份信息。缺少揭示
历史、多来源或不完整结果会明确诊断并跳过该项似然，后续随机揭示不假设独立。
“最大占格藏品轮廓”的对象绑定暂未支持，真实输入遇到该项时回退 v6。

实验模式先进行固定批量先验拒绝采样；支持不足时由 CP-SAT 搜索可行初始状态，再进行
完整块 Gibbs、顺序/身份 MH 与保持统计等式的多身份更新。求解器找到的解不被当作等
概率世界；未完整枚举的条件块不会用于抽样。整数枚举按小块检查截止时间，防止大网格
吞掉整个预算。实验模式默认预算 2 秒，可用 `--conditional-budget-seconds 8` 调整。
初始化和收敛诊断另有少量耗时，预算不是整个界面响应的硬截止时间。

实验模式融合要求收敛检查通过、有效样本数及保留样本数至少 32，监控总价、数量、品质
和各身份的链间差异与自相关。其 v2 权重按支持量限制在 10%–40%；采样失败或支持
不足回退 v6。显式选择原启发式融合时，不给有限世界过滤伪造 ESS 或收敛结论；默认
模式的 v2 权重为零，不把主动禁用融合标成采样失败。
两种模式均不会把有限样本耗尽或超时写成已证明的数值条件无解。
这些阈值是工程门控，不能证明所有模态均已发现，P10/P90 和融合权重仍未校准。
有限预算未收敛结果不会永久缓存，可在相同证据下重新计算；后续尝试使用不同种子，
并记录尝试编号，首次尝试仍保持冻结开发回放的种子。这不保证重试能够收敛。

此修订尚未发布为新版本，也没有重新训练冻结模型。公开事件回放脚本是
`scripts/evaluate_assistant_conditioning.py`：它剔除所有评分局的经验先验行，并将标签
仅用于评分，但冻结模型的训练窗口与公开数据重叠，结果只属开发诊断。公开数据缺少
真实逐轮地图、精确高度和随机揭示对象，不能据此证明布局收益或真实助手的精度提升。

第一版实验采样的固定 15 局事件删减开发对照（每局一个决策），全部决策的 MAPE 为：

| 方法 | MAPE | 新条件采样通过收敛门 |
| --- | ---: | ---: |
| 冻结 v6 | 48.21% | — |
| 旧 40%–80% 融合 | 42.86% | — |
| 新融合，2 秒预算 | 47.59% | 3/15 |
| 新融合，8 秒预算 | 47.59% | 3/15 |

新融合两种预算均有 80% 回退 v6。8 秒增加了未收敛的原始估值数量，没有改善最终
融合；旧融合在这批开发输入上的误差和区间覆盖均更好。因此此次修改是推断正确性与
诊断方面的研究修订，尚不能作为精度升级发布。不能用“有预测”的不同子集比较总体
精度，也不在这 15 局上继续调整权重。逐决策结果、共同子集、覆盖率、耗时、输入和
源码哈希见 [2 秒收据](../../results/assistant-conditioning-development-20261019-stable-2s-sanitized.json)
与 [8 秒收据](../../results/assistant-conditioning-development-20261019-stable-8s-sanitized.json)。
后续整数枚举与多身份更新修复了性能回归，但最终仍只有 3/15 通过收敛门，融合 MAPE
仍为 47.59%；见[最终采样回放](../../results/assistant-conditioning-development-20261019-kernel-v3-2s.json)。

揭示历史修复另用已经消费的 74 局、277 份原报价截止前缀做配对回放。所有输入均核对
原报价的可信前缀哈希，248 张晚于报价写入的地图没有进入特征。只比较同一冻结 v6 的
旧/新适配输入：决策等权 MAPE 为 24.03% → 22.48%，WAPE 为 19.20% → 18.26%；
每局等权 MAPE 为 24.28% → 22.56%。13 局发生预测变化，其中 12 局改善、1 局变差。
这是理想转录的历史开发对照，尚未包含真实 OCR 误差，也不是整个 v6+v2 的盲测成绩。
公开汇总见[真实记录的适配层配对结果](../../results/ocr-reveal-adapter-consumed74-aggregate-20261019.json)。

随后固定同样 277 份输入、全部标签、生成先验与原融合公式，补做完整点预测配对对照：

| 方法 | MAPE | WAPE |
| --- | ---: | ---: |
| A：原适配层 + 原经验库 + 原融合 | 25.58% | 19.85% |
| B：修复适配层 + 原经验库 + 原融合 | 24.25% | 18.99% |
| C：修复适配层 + 清洗经验库 + 原融合 | 24.08% | 18.88% |
| 修复后的 v6 单独输出 | 22.48% | 18.26% |

A 按原发布助手的点预测规则重建，并未运行发布二进制。A/B 共享同一份 v2 结果，
B/C 只改变经验世界准入；277 条均完成，源码/模型在运行中未变，输入与前缀收据全部
匹配。根代理独立复算了 831 个融合点及全部总体指标。经验库与目标局是否重叠未知，
不能将这批已经消费的理想转录数据称为盲测。

修复后的融合仍弱于同批修复 v6 的 MAPE、WAPE。因此在看到上述历史结果后，临时
选择修复 v6 作为默认输出，保留 v2 的诊断及显式实验入口，没有继续调融合权重。
这是事后工程选择，尚未由独立时间块验证；不能把同批回放的 22.48% 当成新对局承诺。
详见[三组完整融合汇总](../../results/ocr-reveal-adapter-consumed74-full-fusion-ABC-aggregate-20261019.json)
与[独立复算及默认策略记录](../../results/assistant-default-point-policy-review-20261019.json)。

右侧运行与诊断日志区保留状态切换、完整 OCR 文本/语义、地图快照、推理契约、
issues、diagnostics 和异常堆栈。日志仅驻留当前进程内存，不写文件；区域可滚动、
选择后复制，也提供“复制全部”和右键菜单。本局清空时日志继续保留，只有用户
点击“清空显示”或退出程序才会消失。

冻结版本复现安装（活动返场前不代表可实际使用）：

```powershell
python -m pip install -e .
python -m pip install -e .\apps\ephemeral-assistant
auction-vision-assistant --models C:\path\to\latest-model-v6-v2.0.0-beta.6
```

按设计，启动后不需要再点击“开始识别”：程序会自动进入大厅监视。需要纠错时直接操作
左侧地图或右侧事件；“立即重扫本轮”只在轮次主界面使用。

若模型尚未下载，可直接使用 `--download-models`；也可以通过
`--model-base-url` 指向兼容镜像。下载器只写入静态模型目录，不写入任何
对局数据。

程序只加载清单中固定大小和 SHA-256 的 `joblib`。Joblib/pickle 文件可能在
加载时执行代码，请勿把同名的第三方文件放入模型目录。
